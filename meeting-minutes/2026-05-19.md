## How to improve visibility of open-source for safe software
- New technologies are needed within future projects
    - IP stack
    - security features
    - cryptography 
- Show that the increasing scope is difficult to handle bare-metal
    - We need a more versatile foundation to implement future requirements
- Layered requirements:
    - Use of modern protocols
    - Necessity to transmit data through that protocol
- Find all applicable norms for safety functions within the industry:
    - Software development: EN 50716
    - Hardware issues: EN 50129
- Provide tooling to create safety artifacts 
    - BASIL: Find out how the artifacts for rail certification needs to look like
    - Strictdoc (Stanislav Pankevich)
- Define subsystem interfaces exhaustively
- How can we use "common ground" as LINUX
- Find set of typical primitives:
    - Cross-comparison
    - Redundancy management
    - Message passing
    - Context management
    - Control flow execution verification
- Identify which requirements are also applicable to automotive or automation
    - Try to use their progress in this field
- Improve visibility towards the other groups within ELISA
    - Show them that we have norms that may differ from the widely known standards
    - Point out differences in the requirements
    - Show that there is a large, global market that adheres to other (maybe unknown) requirements
- Two types of requirements
    - Requirements that are functional for the product
        - (see typical primitives, part of the product)
    - Requirements towards the development process, the tooling, the certification process
- Create proof-of-concept project that we can use as public reference of what the current tooling can do
- Create full set of requirements and implement the code alongside it to show how such a combination can look
- Show code and requirements alongside the same location
